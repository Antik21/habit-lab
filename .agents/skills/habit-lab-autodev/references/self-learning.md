# Progressive memory and self-learning

`autodev_memory.py` is a JSON-only, stdlib helper for one AutoDev run. `start` loads only the navigation index and lessons policy; `plan --tag` selects at most three catalogued records, and `load` returns content while hashing it into `.autodev/artifacts/<run-id>/memory-ledger.json`. After a non-initial load the plan is fixed. `finalize` records outcome, duration, builds, iterations, attempts, platforms, flaky steps, exact reads/writes, and an optional identity for the matching active gate run without a pre-terminal status digest. A successful ledger may use `receipt --source-revision <rev>` to write the strict gate input; the helper derives structural fields and evaluation binding from the gate manifest-to-checked-revision range. Blocked, failed, and partial ledgers preserve their evidence without requiring a promotable composite receipt.

Classifications are local-history only: current entries are `loaded`; prior successful use makes entries `hot` or `stale`; unused entries are `never`; no local successful history is `unknown`. `lint` checks catalog/path and budget integrity, lesson fields, diary wording, duplicate lesson facts, and route-key/destination conflicts. Consolidation emits an advisory every fifth terminal ledger or under lint pressure; it never rewrites memory.

After a sealed terminal-success gate and independent review, `observe-correction` accepts one strict proposal per distinct run. The first is a candidate, the second confirms it, and the third emits deterministic lint/test/helper advice. `store-correction` is the only command that writes a tracked JSON record below `memory/code-corrections/`.

`self-patch-validate` and the explicit confirmed commit command are post-terminal work, not a way to alter the frozen core. They reserve at most one normal isolated Git commit for a strict `memory/instructions/` JSON record attributable to the successful run; the reserve/stage/commit/rollback lifecycle is serialized for this checkout, and an ordinary staging or unchanged-HEAD commit failure releases its reservation. An identical safely retained reservation can resume. `self-patch-record` must then rebind a fresh exact evaluation receipt to that committed HEAD and record digest before the commit is accepted. Scripts, the gate, evaluator, checklist, flows, and policy are frozen denylist paths. A structural instruction record needs a passing evaluation receipt; no command runs arbitrary shell, device, PR, or Git-history-rewrite actions.
