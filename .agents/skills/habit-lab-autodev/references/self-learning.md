# Progressive memory and self-learning

`autodev_memory.py` is a JSON-only, stdlib helper for one AutoDev run. `start` loads only the navigation index and lessons policy; `plan --tag` selects at most three catalogued records, and `load` returns content while hashing it into `.autodev/artifacts/<run-id>/memory-ledger.json`. `finalize` records outcome, duration, builds, iterations, attempts, platforms, flaky steps, and exact reads/writes. `receipt --source-revision <rev>` writes the strict memory receipt consumed by the frozen gate; it binds the checked revision, ledger digest, loaded paths/digests, and a passing lint result.

Classifications are local-history only: current entries are `loaded`; prior successful use makes entries `hot` or `stale`; unused entries are `never`; no local successful history is `unknown`. `lint` checks catalog/path and budget integrity, lesson fields, diary wording, duplicate lesson facts, and route-key/destination conflicts. Consolidation emits an advisory every fifth terminal ledger or under lint pressure; it never rewrites memory.

After a sealed terminal-success gate and independent review, `observe-correction` accepts one strict proposal per distinct run. The first is a candidate, the second confirms it, and the third emits deterministic lint/test/helper advice. `store-correction` is the only command that writes a tracked JSON record below `memory/code-corrections/`.

`self-patch-validate` and the explicit confirmed commit command are post-terminal work, not a way to alter the frozen core. They reserve at most one normal isolated Git commit for a strict `memory/instructions/` JSON record attributable to the successful run; `self-patch-record` must then rebind a fresh exact evaluation receipt to that committed HEAD and record digest. Scripts, the gate, evaluator, checklist, flows, and policy are frozen denylist paths. A structural instruction record needs a passing evaluation receipt; no command runs arbitrary shell, device, PR, or Git-history-rewrite actions.
