# iOS simulator playbook

Read the root [iOS adapter policy](../../../../docs/06-platform-ios.md) only when iOS host or adapter code is affected. Use the [Compose rule](../../../../rules/compose.md) for new or substantially changed common screens.

- Require macOS, the needed Xcode/runtime, and an explicit iOS simulator identifier; physical devices are outside this skill.
- Full simulator/UI verification must use `ui-tests/maestro/run.sh ios <device-id> [run-id]`; only that runner owns build, deployment, UI execution, and canonical evidence. Do not treat a standalone preflight or ad hoc command sequence as equivalent evidence.
- Before any standalone iOS Gradle, build, deployment, test, simulator, or UI operation outside that runner, use the repository-owned [`xcode-preflight.sh`](../../../../../ui-tests/maestro/xcode-preflight.sh) as a toolchain gate and then execute the operation through its checked wrappers. Executing the helper directly gives a concise readiness result only. To run even one operation, source it in the current shell, call its preflight function, and invoke the checked wrapper so the operation inherits the pinned `DEVELOPER_DIR` and exact `xcodebuild` identity without parsing stdout; reuse that shell for a sequence. These standalone operations cannot satisfy full simulator/UI verification or produce canonical evidence. The helper validates the selected toolchain against its single numeric Xcode baseline. The [toolchain catalog](../../../../docs/01-stack-toolchain.md) remains the source of general compatibility and toolchain context; the contributor Xcode need not numerically equal the exact CI pin. If preflight or applicable local compatibility requirements fail, report `blocked` before running any iOS command.
- Select framework/Xcode and simulator-test commands from the [toolchain catalog](../../../../docs/01-stack-toolchain.md) according to the [verification policy](../../../../docs/07-testing-verification.md); use the full runner above for UI verification.
- Keep product UI and navigation shared. SwiftUI/UIKit code remains a narrow native bridge.
- Use the shared semantic automation ID contract exposed through the iOS accessibility bridge. Do not use localized/user/runtime text or coordinates for app controls.
- The sole coordinate allowance is the repository-owned native iOS edge-back system gesture governed by [ADR 0003](../../../../../docs/adr/0003-maestro-cross-platform-ui-automation.md).
- Attribute build, install, launch, assertions, logs, screenshots, and reports to the selected simulator/runtime and source revision.

On a non-macOS host or without the required simulator/runtime, report `blocked`; an Android pass cannot substitute for requested iOS evidence. Do not overclaim minimum-runtime compatibility from a different simulator runtime.
